## Goals / Non-Goals
**Goals:**
- One skill that writes and refreshes the map, with the two E2/E5 traps enforced by a script rather than by the model's care.

**Non-Goals:**
- A candidate-listing script — reopen when two runs on the same tree pick different directories.
- Custom `agents`/`commands` paths declared in a `plugin.json` (the script checks the default folders only; the skill text says to read `plugin.json`) — reopen when a mapped plugin declares one.
- Editing `CLAUDE.md` content or the `instructionFiles` option (E1); deleting `CLAUDE.md` happens only on the user's yes — reopen if the user asks the skill to switch the option.
- Running `/solo:map` on solo itself — its own docs PR after this merges.

## Decisions
- New skill `/solo:map`, not a `docs` mode and not part of `standard`. `standard` writes one ≤20-line root section after a confirm round (E5). `docs` writes reader-facing docs per feature (E6). A mode would put map's safety rules into a skill whose description routes on "README". `deepinit` lost because the skill is a re-runnable refresh, not a one-time init. E5, E6.
- Gates without OpenSpec. The map changes no behavior, so a proposal and delta spec would only restate the directory list. The skill runs its own approve → branch → commit → `/solo:pr-ready` chain. The approval is one AskUserQuestion showing mapped, skipped (with reason) and orphaned directories. The branch is `git switch -c docs/agents-map` when on `main`/`master`. The commit is `docs(agents): map directories` or `docs(agents): refresh map`. pr-ready already handles a branch with no change folder. Lost: plan/execute, which costs an Opus planner pass on a docs refresh. E7, E10.
- Routing. A small repo (a handful of reads) is read inline. Otherwise one `solo:explorer` per top-level directory runs in parallel, returning files, purpose lines as `path:line`, the test command and internal deps. The main thread writes up to a handful of files itself. Beyond that, it sends depth-ordered batches to `solo:implementer` (sonnet) with the evidence, the template, the batch's `AGENTS.md` paths as allowed paths and `check-map.sh` as verification. The execute E7 status-record-and-compare recipe applies. The main thread runs the check and commits. `agents/implementer.md:3` and `README.md:58` add `/solo:map`. E7, E8, E9.
- Selection. The universe is `git ls-files`, so `.git`, ignored builds and venvs drop out. A directory qualifies with ≥3 tracked files directly in it or ≥2 subdirectories holding tracked files. The skill skips hidden (`.`-prefixed), vendored (`vendor/`, `third_party/`, tracked `node_modules/`), generated (`dist/`, `build/`, files whose header says generated), fixture (`fixtures/`, `testdata/`, `__snapshots__/`) and `openspec/` (tool-owned; E8 forbids the implementer there; E17). It always skips `agents/`, `commands/` and `output-styles/` under a plugin root (a dir with `.claude-plugin/plugin.json`) or under `.claude/`. Top-level dirs without a file still get an unlinked Map row. On solo this maps `skills/`, `skills/plan/scripts/` and `skills/pr-ready/scripts/`, and gives `agents/`, `tests/` and `openspec/` rows only. E2, E3.
- Format. A nested file is `<!-- Parent: <rel>/AGENTS.md -->`, pointing at the nearest mapped ancestor, then `# <dir>/`, then `## Purpose` (one paragraph), `## Key files` (`| File | Purpose |`, every tracked file directly in the dir, up to 15, then `+N more`), `## For AI agents` (the test command plus ≤3 rules, each with `path:line`) and `## Dependencies` (internal dirs, external tools). The root gets only `## Map` (`| Directory | Purpose |`), replaced in place or appended at the end. Every other root line is kept, and `## Coding standard` byte for byte. Lost from E4: timestamps (a no-op re-run would diff; git has dates), per-file Subdirectories tables (the root Map is the one index), visible-prose Parent line (Claude Code loads ancestor files itself (E1), so the comment serves humans and the check; stripped or not, it costs nothing). E1, E4, E5.
- No generated/hand-written markers. Table rows are keyed by their first-column path: a row stays (with its cell) while the path exists, new paths get rows and gone paths lose them. Every other line is kept unless code proves it false, citing `path:line` (the docs rule, E6). A dir that stops qualifying becomes an orphan: the question shows its hand-written lines, and on yes it is `git rm`'d and its Map row dropped. A deleted dir loses only its Map row. Lost: begin/end markers (noise in every file), and `## Manual Notes` (edits elsewhere would be overwritten). E4, E6.
- `check-map.sh [base-ref]` (default `HEAD`) sources `../../plan/scripts/common.sh` (E12). Over `git ls-files -co --exclude-standard -- AGENTS.md '*/AGENTS.md'` it fails, naming the file, on three things. First, a file whose parent folder is `agents|commands|output-styles` and whose grandparent holds `.claude-plugin/plugin.json` or is named `.claude`. Second, a relative `](target)` link or `<!-- Parent: x -->` (anchor stripped; `scheme:` and `#` links ignored) that does not exist relative to the file. Third, when `<base>:AGENTS.md` has `## Coding standard`: that section (heading to the next `## `, trailing blank lines dropped) differs from the working copy's. It prints `check-map.sh: ok` on success. This is a script rather than prose because the three checks are the safety contract and must behave the same every run (`README.md:88` — `so every run does the same thing`). E2, E3, E12.
- CLAUDE.md repos: when any E1 `tit` file exists at the root, the report says nested files load only with `instructionFiles: claude-md-and-agents-md`, then AskUserQuestion whether to delete that `CLAUDE.md` so they load; it is deleted (`git rm`, in the same commit) only on a yes, and `instructionFiles` is never changed. E1.
- Version 2.1.0 (new skill, minor). Descriptions in `plugin.json:4` and `marketplace.json:9` gain `map`. README goes to 15 skills / 10 helpers, with a skill row after `standard`, a Scripts row and a Tests entry. `AGENTS.md:6`, both lefthook test jobs and the CI tests step add `bash skills/map/scripts/check-map.test.sh`. E13, E14, E15.

## Risks / Trade-offs
- Prose-only behaviors (selection, re-run keep rules, approval) are checked by guards text greps, not by running the skill (E11 pattern).
- Local `main` was behind `origin/main` when this was planned (diblaze/solo#4 is merged). Execute must branch from an up-to-date `main`.
- Unverified: that Claude Code strips HTML comments from instruction files (E4 says so; the binary has a stripper, but I did not trace its use for `AGENTS.md`). The decision holds either way.
- Unverified: whether a user-level `~/.claude/CLAUDE.md` counts as a project `CLAUDE.md` for E1. The user reports solo's `AGENTS.md` loading, which suggests it does not.

## Open Questions
- none. Resolved 2026-10-22 by the owner: in a repo with a `CLAUDE.md`, write the nested files anyway, warn that they will not auto-load, and ask whether to delete the `CLAUDE.md`; delete only on a yes.
